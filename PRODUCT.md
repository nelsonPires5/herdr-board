# Stem Board

## Register

product

## Users

Developers who coordinate several coding agents from a terminal and need to understand, dispatch,
and recover work without leaving their current session. They may use the board locally, through a
remote terminal, or inside a host such as Stem or Herdr.

## Product Purpose

Stem Board turns agent work into a visible, durable pipeline. It keeps cards, execution state,
agent output, and human review connected while letting the terminal host remain responsible for
sessions, panes, and navigation. Success means a developer can see what is running, intervene when
needed, and resume work without reconstructing state from separate terminals.

## Brand Personality

Focused, legible, and operational. The interface should feel like a trusted terminal tool: compact
enough for sustained use, explicit about state, and calm when several agents are active.

## Anti-references

Avoid decorative dashboards, novelty terminal effects, excessive borders, color used without
meaning, and layouts that hide state behind modal navigation. Do not imitate generic web Kanban
boards or make the interface depend on color alone.

## Design Principles

1. Keep current work and its state visible.
2. Use familiar terminal interactions and predictable keyboard navigation.
3. Give every color and symbol a semantic role.
4. Preserve useful density while keeping focused controls readable.
5. Let the board integrate with its host without losing its own configuration or identity.

## Accessibility & Inclusion

State must remain understandable without color through labels, symbols, and borders. Themes need
readable foreground/background contrast, usable focus indication, terminal-palette compatibility,
and stable behavior across dark and light terminals.
